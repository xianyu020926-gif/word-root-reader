# 架构与安全

## 现在的结构

- `app/` 与 `public/`：PWA 界面、离线壳与同源 AI 后端。
- `app/api/deepseek/route.ts`：提示词、输入约束、模型调用和结果核验的唯一云端入口。
- `platforms/desktop/`：Windows Electron 壳；Key 仅保存在运行内存/会话中。
- `platforms/android/`：Android Capacitor 壳；使用原生网络能力直连模型。
- 文章档案、单词本、学习断点：先保存在设备 `localStorage`；PWA 登录后同步到当前账户，仍支持手动备份导入导出。
- `server/multiuser.mjs`：账户、密码哈希、签名会话、个人云档案和限流。

## Key 的两种模式

### 用户临时 Key

适合公开部署。Key 不进入仓库、不写入应用文件、不进入本地长期档案，关闭标签页或应用即清除。每个用户承担自己的模型费用。

### 私有云端托管 Key

适合本人或小范围使用。服务器环境变量设置 `DEEPSEEK_API_KEY` 后，前端不再需要填写 Key。这个模式只应在站点有登录或访问白名单时使用。仓库和浏览器均看不到服务器 Key。

## 防止模型乱编

- 原文被明确标记为资料，不执行其中的提示或命令。
- 翻译必须逐段、逐句对齐；段落数和句子数由程序复核。
- 只允许处理用户亲自选择的词，返回词数和词面必须完全一致。
- 语境词义必须附带当前句中的逐字证据。
- 构词关系不可靠时必须标为低可信并降级成整词记忆，不允许硬拆。
- 语法回答必须以当前句为证据；证据不在句中则拒绝结果。

## GitHub 与云端的分工

GitHub 负责源码、历史版本、测试和安装包构建。运行时密钥只存在部署平台的加密环境变量中。当前 PWA 继续使用受访问控制的私有站点；将来迁移其他云平台时，只替换部署层，不改学习核心。

## 多人使用边界

0.16 已加入邀请码账户、个人云档案、AI 请求限流和每日备份。当前默认仍让每个人填写自己的临时 Key；若以后启用共用模型 Key，需要先确定每人额度、费用承担方式和异常用量告警。
