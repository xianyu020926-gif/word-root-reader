# 单点穿透词汇学习：产品需求基线

更新时间：2026-09-08

## 不可偏移的原则

1. 产品核心是学习词汇，不是完成一次阅读课程；文章只负责兴趣、真实语境和文化信息。
2. 原文绝不改写、删减或替换，只能叠加译文、声音、词卡和学习状态。
3. 目标词由用户主动选择。系统可以解释词的作用，但不替用户决定“哪些词值得学”。
4. 面向注意力容易分散、需要在较短时间积累大量阅读词汇的用户；一次只给一个清楚动作，不堆信息、不强迫连续打卡。
5. 不以拼写训练为核心。目标是看到、听到时能识别，并能在阅读中理解。
6. 语法是可按需进入的旁路资料库，不插进词汇集中学习四步，也不由系统强迫用户学习。

## 固定学习路径

1. 导入用户感兴趣的原文。
2. 听整篇朗读，获得整体声音记忆；查看极短大意或段落译文。
3. 用户在原文中点击不懂或不确定的词，组成有上限的本篇词单。
4. 点词时只在原句下方展开该句译文；词卡显示在右侧，不遮挡原文。
5. 确认词单后进入集中学习：核心语境义 → 发音 → 可靠的词根/词缀或直接记忆 → 回扣原段并朗读 → 短暂找回测试。
6. 完成一个词的学习后才进入“学过的单词本”；单纯点击或加入词单不算学过。
7. 以后遇到旧词，复用稳定的词根、词源和历史语境；当前句中的具体词义仍需重新判断。
8. 学过的词按轻量间隔进入复习队列；每次最多 10 个，只做主动找回，不强迫回到原文，也不设置连续打卡。

## 界面规则

- 电脑和平板：每段一行，左边原文、右边整段译文。
- 手机窄屏：同一段内先原文、后译文，不强行挤成两窄列。
- 点开单词时：当前句译文必须在原句下方，整段译文仍在右列。
- 同一时刻只强调一个句子或一个单词；其他内容降低视觉权重。
- 颜色只表示当前焦点和少量状态，不能给整篇文章铺满彩色单词。
- 整篇朗读时只轻微标出当前正在读的一句；任何时刻仍只有一个声音焦点，停止后立即清除。
- 所有错误选择都应容易撤销；选错词可以删掉并换词。

## 数据与模型

- DeepSeek 负责全文理解、两版译文、语境词义、词根词源与问答。
- 内置语法库负责稳定的基础框架；文章中的具体语法疑问由“问老师”结合完整原文与当前句解释，先讲句子主干，不堆术语。
- 语法回答必须附带可在原文逐字找到的依据，并标注可信度；证据不足时明确说不确定，不得编造结构、纠错或原文例句。
- 朗读使用独立 TTS，不依赖 DeepSeek 多模态。
- 单词本保存词义、结构、来源文章、原句、学习次数和最近学习时间。
- 当前把学过的单词和已分析文章保存在设备本地；相同原文再次导入时复用翻译与已有词卡，缺少的新词再请求 API。
- 0.13 支持不含 API Key 的学习档案导出、校验与合并恢复；当前仍明确为设备本地数据，跨设备自动同步留待后续设计。
- API 返回不完整时不得把残缺词卡当作成功。
- 构词拆分必须带置信度和简短依据；置信度低时退回整体记忆，不把猜测性拆分展示给用户。
- 语境词义请求必须携带用户实际点中的句子和段落；模型返回的依据必须能在该句中逐字核对。
- 翻译结果必须逐段、逐句编号对齐且非空；结构不完整时整次拒绝，不落入文章档案。

## 每次发布前检查

- 原文是否保持逐字不变。
- 段落左右是否一一对应。
- 句译是否只出现在被点击句子下方。
- 选词、删词、换词和数量上限是否有效。
- 集中学习是否按词逐个推进。
- 未答测试是否不能记为“学过”。
- 单词本是否能保存、搜索、朗读和删除。
- 语法库是否可搜索，且没有打断词汇主流程。
- 点词后的“问这句语法”是否携带当前句、语法框架，并拒绝无法回到原文核对的回答。
- 旧词的新语境义是否重新判断。
- 已分析文章能否进入档案，相同原文能否免去重复分析。
- 旧词进入新文章时是否区分“可复用结构”和“待重新判断的本句词义”。
- 同一个词重复出现时，集中学习是否回到用户实际选中的句子和段落。
- 到期复习是否最多 10 个、答题前不能继续、答错后更早再出现。
- EXE、APK、PWA 是否使用同一套交互。
- 中途退出是否能回到原词、原步骤；已揭示的测试答案不能恢复成“已记住”。
- 单词本复习与文章学习断点是否分别保留；结构搜索是否只利用已有、有依据的构词记录。
- 更换文章、修改词单后，旧 AI 请求是否不能污染当前文章和词卡。
- 档案超过 15 篇是否仍保留，保存失败是否明确提示，恢复备份失败是否回滚。
- 手机词卡是否留在当前句附近且不遮住句译，刷新翻译后词卡是否仍可打开。
